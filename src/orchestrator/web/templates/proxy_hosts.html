How this page works

Traefik Manager is the source of truth for routes. A router_provider: traefik host is live-managed: adding, editing or deleting it also adds/edits/deletes the real route on Traefik Manager (an upstream is required for that — a blank one keeps it a local-only reference). pangolin/npm/other hosts stay local-only reference records, since no adapter exists for those backends yet.

Edits change the live DB (and, for a live-managed host, the real route) — nothing is written to services.yaml until you Save to YAML, or discarded until you Reset to saved. A host with no linked service stays DB-only.

Traefik column: matched a live router covers this hostname; missing Traefik is reachable but has no matching router; unknown Traefik Manager is not configured or the last poll failed — not the same as "missing". Below it, the router's own verdict from Traefik: router enabled or router error with Traefik's message (for example entryPoint "https" doesn't exist — edit the host and pick an entry point that exists). Entry points shows what the host is bound to.

Enabled switches a host off without deleting it. For a live-managed host the route is parked on Traefik Manager (its own disabled-routes store), so Traefik stops serving it and the Traefik column shows disabled rather than an error; Enable puts the exact same route back (with its HTTP → HTTPS redirect, if it has one). A disabled live-managed host has to be enabled before it can be edited. Tick several rows to enable, disable, delete or change wake on hit in one go.

Resync pulls Traefik Manager's current routes into the DB: it imports routes with no local record yet ("Discovered" below) and catches drift on linked hosts. See docs/proxy_hosts.md.
