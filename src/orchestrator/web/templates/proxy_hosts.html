How this page works

This database is the working copy; Traefik Manager is written only when you push. Adding, editing, enabling/disabling or deleting a router_provider: traefik host (with an upstream) changes the local record only. Save to YAML writes services.yaml and then pushes every pending change to Traefik Manager; Push now pushes without saving the YAML. Reset to saved discards unsaved edits (including pending deletions). pangolin/npm/other hosts stay local-only reference records, since no adapter exists for those backends yet.

Push status (first badge in the Traefik column): pending edited here, not pushed yet (or the route does not exist yet); detached nothing was edited here but Traefik Manager differs (enabled state, upstream or entry points) - someone changed it there, and Push puts it back; external the route is not ours (adopted by Resync or hand-written): its content is never overwritten, only its on/off state is pushed; in sync. Hover a badge for what differs.

Traefik column, below it: matched a live router covers this hostname; missing Traefik is reachable but has no matching router; unknown Traefik Manager is not configured or the last poll failed — not the same as "missing". Then the router's own verdict: router enabled or router error with Traefik's message (for example entryPoint "https" doesn't exist — edit the host and pick an entry point that exists). Entry points shows what the host is bound to.

file: under a hostname is the Traefik Manager config file its route lives in. New routes are created in the file TRAEFIK_MANAGER_CONFIG_FILE resolves to (default <service>.yml; a host can override it in its form). A route that is somewhere else - say _shared.yml - is only flagged, never touched by a push; Move relocates it, on request.

Enabled switches a host off without deleting it - locally; the route is parked on Traefik Manager (its own disabled-routes store) when the change is pushed. Tick several rows to enable, disable, delete or change wake on hit in one go (also local until pushed).

Resync pulls Traefik Manager's current routes into the DB: it imports routes with no local record yet ("Discovered" below) and adopts their upstream and on/off state for linked hosts, which then count as in sync. See docs/proxy_hosts.md.
