Safety rail for the unattended wakes: the traffic-driven auto-wake (see docs/traffic_metrics.md) and the maintenance page, which shows "not available" instead of starting this service while it is off. The host (node) has the same switch. Does not affect the manual wake button, the CLI or the wake API. What a visit to this service while it is down does, when Wake on hit is on. Any request: the maintenance page starts it straight away. Start button: the page shows a Start button and nothing starts until someone presses it, so scrapers, monitors and apps polling the URL cannot wake it by accident (the traffic-driven auto-wake skips these services). Hard exclusion with no override — e.g. the VM hosting the PBS datastore.
